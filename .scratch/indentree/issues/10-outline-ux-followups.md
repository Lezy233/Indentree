# 10 — 大纲交互修订：空白手势、选择/编辑互斥、撤销、删除区、动作菜单

**What to build:** 用户在第一轮手测后提出的交互修订——① 打开空白处单击取消选择、双击空白处在目录末尾新建条目（层级规则 A：与文档最后一个条目同级同 kind，名称默认「新条目」且全选）；② 选择状态与编辑状态二选一：进入选择态后，点击行内手柄右侧任意位置（含 checkbox）即切换该行选中，双击不再进入编辑；③ 大纲侧改动（改名 / 排序 / 缩进 / 新建 / 删除 / 拖拽落点）统一支持撤销，绑定 ⌘Z；同时补齐无键盘（手机）用户缺的入口：拖拽时的「拖到此处删除」通栏（批量删除二次确认）、常驻「＋」动作菜单（末尾新建 / 撤销 / 删除选中项）。

**Blocked by:** 08 — 大纲拖拽：MultiDrag 整体拖拽 + 拖入式三区落点

**Status:** ready-for-agent

- [x] 单击大纲空白处取消选择；双击空白处在末尾新建「新条目」（同级同 kind、名称全选、直接进入编辑）
- [x] 选择态与编辑态二选一：选择态下点击行（手柄右侧）切换选中，双击不进编辑；Enter（键盘）仍可进入编辑
- [x] 手机拖动翻页 / 鼠标划选（位移 > 10px）不算点击，不会误切换或误清空选择
- [x] 撤销：改名 / 排序 / 缩进 / 新建 / 删除 / 拖拽落点全覆盖，⌘Z 生效；行内编辑框与 Markdown 栏聚焦时不接管（行内编辑需先 Esc/失焦退出，见已知取舍①）
- [x] 拖拽时浮出底部「拖到此处删除」通栏，指针进入高亮；拖拽集 ≥2 项时二次确认，单项直接删
- [x] 常驻「＋」动作菜单：在末尾新建条目 / 撤销（栈空置灰）/ 删除选中项（无选择置灰，≥2 项走确认）
- [x] 手机适配：checkbox 热区 24px、拖拽手柄 `touch-action: none`

## Comments

- 2026-10-08 实现完成（承接用户在 ticket 08 之后提出的修订意见）：
  - **决策记录（讨论后确认）**：
    - 末尾新建用**规则 A**：与文档最后一个条目同级同 kind 追加在它后面——扁平列表里就是顶级新条目；
      文档结尾是嵌套项时加在同一层（「始终顶级」在文档以标题小节结尾时无法被 markdown 还原）；
      结尾是叶子块时退回列表项。空文档建第一个顶级列表项。
    - 选择态 = 当前有选中项（≥1），不引入独立状态位；点已选中行 = 切换为取消选中；
      双击行在选择态下用 `event.detail >= 2` 忽略第二下，保证「双击 = 一次切换」；
      Enter（行聚焦）在选择态下仍可进入编辑（只有指针点击受「二选一」约束）；
      选择态下拖未选中的行维持原行为（只搬它一个并清空选择）。
    - 撤销：一次用户动作 = 一步（「改名 + 缩进」记成一步）；无变化不入栈；
      Markdown 栏改动后清空大纲撤销栈（否则会连带回滚文本区的改动）；不做重做；
      手机入口放在「＋」菜单里。
    - 删除区：底部通栏（拇指可达），拖拽时才出现；确认范围只针对「拖入删除区的批量删除」，
      键盘 Delete 不加确认（桌面有 ⌘Z 兜底）。
  - **纯函数**（新增 11 个单测，全套 110 全绿）：
    - `src/outline-history.mjs`：不可变快照栈 `emptyHistory / canUndo / pushHistory / undoHistory`，
      上限 50；快照 `{ tree, selection }` 由页面决定，模块只当不可变值（我们的操作返回新树，结构共享）。
    - `src/outline.mjs` 新增 `appendItem(root, text)`（规则 A）。
  - **页面接线**：
    - 空白手势：`outline-body` 上单击空白 = 取消选择；双击空白 = `createItemAtEnd()`（`startEdit(path, { selectAll: true })`）。
    - 选择/编辑互斥：行点击在选择态下走 `toggleSelection` / `extendSelection`（Shift），并先做
      「按下→松开位移 ≤ 10px」的手势判定（手机翻页、鼠标划选都不算点击）；空白的取消选择同样受该判定保护。
    - 撤销：`withHistory(change)` 包住每条改动路径（改名提交、Enter/Tab/Backspace、拖拽落点、删除、末尾新建），
      比较序列化文本后才压栈；`⌘Z` 在 document 层拦截（输入框 / Ace 内不接管）。
    - 删除区：拖拽 `onStart` 显示 `.on`，pointermove 命中时 `.hot`；`onEnd` 先判定落点再隐藏，
      命中即 `deletePaths(dragPaths, { confirm: true })`（≥2 项弹确认条）。
    - 「＋」菜单：常驻按钮 + 弹出菜单（`role="menu"`），撤销 / 删除项按可用性置灰；点菜单外或 Esc 关闭。
    - 手机适配：checkbox 外面包一层 `label.sel-hit`（热区 24px，点击由原生转发到 input，
      我们的监听只认 `.sel-box` 避免重复切换）；手柄加 `touch-action: none`。
  - **实装踩到的两个坑（已修）**：
    ① 手势位移判定必须放在点击处理最前面——否则「拖动翻页」会落到「点空白」分支把选择清掉；
    ② 「＋」菜单与确认条是绝对定位，但 `.col` 没有定位祖先，第一次实现跑到了 `main` 右边缘（树形图栏上方）
    → 给 `#col-left` 加 `position: relative`。

    手柄不改变选择、非选择态行点击不选中、Enter 仍可编辑、拖动不误切换、
    ⌘Z 撤销改名/删除（含恢复选择）/缩进/拖拽/末尾新建、无变化不入栈、文本区改动清栈、
    焦点在 Markdown 栏不接管、删除区浮出与高亮、单项直删、批量确认（取消不删 / 确认删 + 可撤销）、
    菜单三项及置灰、点外关闭、checkbox 热区与手柄 touch-action；

  - 抽 `makeNode(kind, text, level)`：`insertSibling` 与 `appendItem` 不再各写一遍「造节点 + 带 level」。
  - 去掉页面里重复的 `'新条目'` 字面量（直接用 `appendItem` 的默认文案，单一来源）。
  - 去掉三个没有调用者的调试钩子（`undo` / `openMenu` / `isMenuOpen`）；`HISTORY_LIMIT` 保留导出

  - `updateMenuState()` 不再搭在 `applySelectionVisuals` 里（函数名只说视觉），改由选择变化 / 重渲染 / 改动入栈处调用。

  ②撤销栈只跟踪大纲侧改动，Markdown 栏改动会清空它；不做重做；
  ③「新条目」名称全选后直接输入即覆盖（IME 组字时同理，符合「新建即改名」的预期）。
