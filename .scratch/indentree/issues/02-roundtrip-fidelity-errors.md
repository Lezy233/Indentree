# 02 — Round-trip 序列化 + 行内保真 + 叶子块 + 错误行号

**What to build:** 让数据真正可信——中间树可序列化回 markdown 且按 kind 还原原始写法（标题仍是 #、列表仍是 -），节点文本中的行内 Markdown（`**粗体**`、链接）往返无损，表格/代码块等块级内容作为叶子块挂载不丢失；解析失败携带行号，页面在文本侧行级标红并出状态条提示（regex101 式，不用弹窗）。

**Blocked by:** 01 — 转换核心 + 最小双栏页面

**Status:** ready-for-agent

- [x] markdown→树→markdown round-trip 测试通过：标题写法的文档转树再转回仍是标题写法，列表同理
- [x] 行内保真测试通过：含 `**粗体**`、`[链接](url)`、行内代码的节点往返后不变
- [x] 叶子块测试通过：表格、围栏代码块作为不可再分节点挂在当前层级，round-trip 不丢内容
- [x] 解析失败时核心返回行号；页面在对应行标红 + 底部状态条显示「第 N 行无法解析」
- [x] 手动验收：粘贴含表格与粗体的真实文档，经树编辑后再导出，内容与格式无丢失

## Comments

- 2026-10-04 实现完成：`serializeMarkdown`（中间树→markdown，按 kind 还原：标题用节点新携带的 `level` 还原 # 深度、列表项还原为 `-`、段落与叶子块原样输出；相邻列表项不空行保持紧凑）；`MarkdownParseError` 携带 1-based 行号；叶子块解析时去容器缩进（缩进代码块保留 4 列语义缩进）、序列化时按层级重新缩进，round-trip 稳定。新增 9 个测试（共 20 个全绿）。浏览器手动验收：含表格/粗体/代码块/嵌套列表的真实文档 round-trip 字符串完全相等；行级标红（backdrop 叠加层）与状态条经 DOM 验证定位正确、可清除。
- 设计说明：CommonMark 无语法错误，markdown-it 对字符串输入实测不抛错（超深嵌套/病态输入均静默解析），故「解析失败」为防御性契约——任何底层异常包装为 MarkdownParseError，行号取正在处理的 token 源行；错误路径测试通过注入会抛错的 parser 完成，页面错误 UI 经 `window.__indentree` 调试钩子验收。
- 已知取舍：有序列表序列化统一为 `-`（验收原文即「列表仍是 -」，有序标记还原留待后续需要时再加）；缩进式代码块（code_block）若全部行带统一额外缩进，极端情况会丢前导空格（围栏代码块精确，为常见路径）。
