# 大纲视图采用拖入式嵌套 + 同父多选约束

状态：accepted

大纲视图的拖拽采用「拖入式嵌套」（落点 inside 区域 = 成为子节点，between 区域 = 排序），而非 Notion 的「拖拽纯排序、层级仅靠缩进操作」。多选附加同父约束：所有选中项必须共享同一父节点；选中父节点时后代自动跟随（子树整体参与任何操作）。配套规则：Shift 连选越界时截断到同父范围并状态条提示；全选语义为「选中所有顶级节点」；落点为任一选中项自身或其后代时显示禁止样式、松手无效。

为什么：拖入式嵌套是 Workflowy / Dynalist 品类的主流行为，比排序+Tab 更直观（交互成本换取实现复杂度，已知情接受）。同父约束是让多选下四种操作（整体拖拽/缩进/取消缩进/删除）语义良定义的关键——跨父多选时这些操作没有干净答案，且 SortableJS MultiDrag 对互相嵌套的选中项视觉反馈混乱。选中即选子树是文件管理器已有的心智模型，不引入新规则。

被否决的替代方案：Notion 语义（拖拽纯排序）——实现简单但与用户对「类似 Notion 操作逻辑」的实际期望（拖入式）不符；跨父多选——语义歧义，见上。

后果：落点需要 above / inside / below 三区反馈与循环检测（非法落点禁止样式），是 B 方案的固定实现成本；后续若改回排序语义，工具栏缩进操作已存在，回退路径保留。

## 修订 2026-10-08（用户反馈）

多选只保留「MultiDrag 整体拖拽（ticket 08）」与「批量删除（Delete 键）」两个出口：**删除浮动工具栏**（n selected / 缩进 / 取消缩进 / 删除按钮）与**全选**；标题栏留一个「取消选择」（有选中项时才出现）。缩进 / 取消缩进退回单节点键盘操作（Tab / Shift+Tab），与多选解耦。

为什么：缩进 / 取消缩进 / 全选在实际使用场景里用不上；而选中的那一刻浮出工具栏会把大纲内容整体下移，用户明确不接受这种偏移（「取消选择」因此改为绝对定位，出现/消失不改变标题栏高度）。

后果：同父约束仍然必要——它是 MultiDrag 与批量删除语义良定义的前提；Shift 连选越界截断与同父约束提示保留；「全选 = 所有顶级节点」的语义作废（本 ADR 正文中相关表述以本修订为准）。
